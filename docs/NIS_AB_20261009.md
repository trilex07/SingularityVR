## Sharpness fix + live tuning row — 2026-10-09 (evening)

**Reported:** NIS sharpness makes the image "different" — sharper, but
distorted/haloed. Diagnosis (official NIS v1.0.3 `NVScalerUpdateConfig`
curve, measured):

```
sharpness  USM strength range (min .. max)
0.10       0.00 .. 0.34
0.20       0.04 .. 0.66   <-- new VR default
0.35       0.22 .. 1.13   <-- old default (aggressive in VR)
0.50       0.40 .. 1.60   (NVIDIA's stated "default")
1.00       1.15 .. 2.73
```

The USM strength ramps from min (at luminance `kSharpStartY`) to max (at
`kSharpEndY`). At the old 0.35 default, **bright areas get strength ~1.13** —
visible halos/ringing through the headset lenses, and the luminance-dependent
ramp makes the sharpening uneven. That is the "sharper but different" look.

**Fix (two parts):**
1. Default `Sharpness` lowered **0.35 → 0.20** (code default + shipped INI).
   Bright areas now reach only ~0.66 — gentle, even sharpening.
2. **New live hub row `UPSCALER SHARP`** on the ADVANCED page (enum
   `PR_NISSHARP`, next to `UPSCALER NIS`). Steps ±0.05 over [0,1], snapped to
   2 decimals, persisted to `[Upscaling] Sharpness` on panel close. The
   per-eye dispatch reads `g_nis.sharpness` every frame, so the next frame
   already shows the new strength — **same-spot A/B without a relaunch.**

**A/B test plan (one variable at a time, NIS mode constant):**
1. `UPSCALER NIS` = `NISSharpen`, `RenderScale` = 1.00, `OutputScale` = 1.00.
2. Stand at a fixed high-contrast spot (textured wall / bright edge).
3. Step `UPSCALER SHARP`: **0.00** (baseline, no sharpen) → **0.20** (new
   default) → **0.35** (old default). L3+R3 screenshot at each.
4. Expect: 0.20 reads clearly sharper than 0.00 but WITHOUT the halos/"wrong"
   look of 0.35. If 0.20 is still too much, step down to 0.10–0.15.

Building on the `fix/vr-menu-input-grip-performance` worktree; the change is
in `d3d9.cpp` (enum/layout/renderer/save/adjust + default) and `nis_bridge.h`
(struct default). `d3d9.dll` rebuilt (`/O2`, PE32) and deployed to game
`Binaries` (SHA-256 `E641B9F9…`).

## Runtime verification checkpoint — 2026-10-10

The current `test-nis-upscale.exe` policy suite passes **167/167**. An archived
Steam+xrsim run with `Mode=NISSharpen`, `Sharpness=0.20`, and both scales at
1.00 logged one official NIS 1.0.3 initialization and seven measured-dispatch
windows, versus 302 windows with no dispatch. The measured sample reports
`2112x2304 -> 2064x2208`, one frame, and a `0.001 ms` stage copy; its GPU time
rounds to `0.000 ms`, so it is not a usable cost measurement. No matching
same-scene image A/B was collected. This proves the dispatch path is reachable
under the simulator, not that sharpness 0.20 looks better or that it improves
frame time. Keep `Mode=Off` as the shipped default until a controlled visual
A/B is captured.

Evidence: [`runtime-summary.json`](../deployment/nis-runtime-20261009-234442/runtime-summary.json)
and the hash-identified original [`view_matrix.log`](../deployment/nis-runtime-20261009-234442/view_matrix.log).
