# Valkyrie / Volk insertion comfort (SIDE, L1/L2 only)

Base: physically accepted shoulder-pickup source `bb234ba`. Steam was not touched.

The magazine FSM tests distance from the physical left hand to the native clip-joint socket only on Grip release while carrying a fresh magazine. The original single 16 cm radius in `weapon_reload_dispatch.inl` applied to Valkyrie, Volk and Kasimov. `ReloadInsertRadiusCm` in `d3d9.cpp` belongs to Centurion and did not control this path. The socket is witnessed from the weapon's original clip joint, not a guessed world-space point. An older failed M01 trace contained off-target releases at 22.5 cm or farther; it does not prove that 18 cm eliminates all missed inserts. The accepted `bb234ba` physical report establishes pickup, not the new insertion radius.

This branch adds independent `ValkyrieInsertRadiusCm` and `VolkInsertRadiusCm` (default 18, accepted 16..20). Values outside that range fall back to 18. Kasimov remains 16; Centurion remains on its own setting. Increasing from 16 to 18 cm changes only a 2 cm shell around the same measured socket. The core still requires the exact live pawn/weapon witness, carried-magazine ownership, valid tracking/ammo, Grip release and no support Grip. A failed or distant release discards the magazine. No shoulder acquisition, wrist producer, native inventory or stereo draw code changed. Event logs now include `socketDist` and `socketRadius`, permitting physical false-insert checks.

Offline: `test-dual-weapon-tmd.ps1 -SkipOled` PASS, including 30,000 transactions and 16/18/20 cm inside/outside, support and stale-owner checks; x86 PE32 `/O2` build PASS. `test-tmd-runtime-regressions.ps1` passed CPU tests through locker layout but its D3D9 HAL fixture is BLOCKED by desktop `CreateDevice` failure (same environment limitation, not physical evidence). No PSVR2 validation of the 18 cm setting yet.
